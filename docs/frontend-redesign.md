# OpsEngine 前端重设计

本文是前端视觉与交互重构的设计基线。**目标：暗色风格、简洁明了、关键流程顺畅**。

本文不是一次性开发清单，而是后续 UI 落地的统一参考。所有页面/组件改动都应回到这里对照 token 与交互规范。

---

## 1. 设计哲学

| 原则 | 意思 | 反例 |
|---|---|---|
| **暗色优先** | 默认深色背景，亮色信息优先；不再做浅色模式，集中维护一套 | 双主题切换 |
| **任务导向** | UI 围绕"我要做什么"组织，而非"按对象分类" | 现在的 6-tab 信息架构 |
| **就地反馈** | 用户在哪触发动作，反馈就在哪附近出现；尽量避免"跳到另一个 tab 看结果" | 现在的"保存为报告 → 自己去文档 tab 找" |
| **可观测** | 长流程实时显示进度，工具调用可见、可追溯 | 一个 spinner 黑盒等几十秒 |
| **简单不简陋** | 元素少，但每个元素都有功能；不靠装饰填空间 | 大色块 + 模糊背景 + 圆角招贴风 |

## 2. 视觉系统（Design Tokens）

### 2.1 颜色

整体走 **Claude.ai 偏暖深色**：底色 zinc/neutral 暖灰系，主色用琥珀橙（与现在 Claude 一致）。

#### 背景层级

| Token | 颜色 | 用途 |
|---|---|---|
| `bg-canvas` | `#1A1A19` | 最底层画布（页面背景） |
| `bg-surface` | `#262624` | 列表项、卡片、对话气泡 |
| `bg-elevated` | `#2F2F2C` | 浮层（Drawer / Dialog / Popover） |
| `bg-input` | `#1F1F1D` | 输入框背景（比 surface 略暗以与卡片区分） |
| `bg-overlay` | `rgba(0,0,0,0.6)` | Dialog 蒙层 |

#### 文字与描边

| Token | 颜色 | 用途 |
|---|---|---|
| `text-primary` | `#F5F4ED` | 标题、正文 |
| `text-secondary` | `#A8A6A1` | 次要描述、时间戳 |
| `text-tertiary` | `#6B6962` | 占位文本、禁用状态 |
| `text-inverse` | `#1A1A19` | 在浅色 chip / 主色按钮上的字 |
| `border-subtle` | `#3A3A36` | 卡片、分割线 |
| `border-strong` | `#4A4A45` | 输入框、活跃描边 |
| `border-focus` | `#D97757` | focus ring（与主色一致） |

#### 主色与状态色

| Token | 颜色 | 用途 |
|---|---|---|
| `accent` | `#D97757` | 主操作按钮、链接、focus | 
| `accent-hover` | `#C66948` | hover 态 |
| `accent-soft` | `rgba(217,119,87,0.15)` | 主色 chip / 高亮背景 |
| `success` | `#10B981` | 成功状态、工具调用完成 |
| `success-soft` | `rgba(16,185,129,0.12)` | 成功 chip 背景 |
| `warning` | `#F59E0B` | 警告、追问、过期 |
| `warning-soft` | `rgba(245,158,11,0.12)` | 警告 chip |
| `danger` | `#EF4444` | 失败、删除、报错 |
| `danger-soft` | `rgba(239,68,68,0.12)` | 错误条背景 |
| `info` | `#60A5FA` | 中性提示（与主色区分） |
| `info-soft` | `rgba(96,165,250,0.12)` | 信息条背景 |

#### 语义映射（强制约定）

| 含义 | 用色 |
|---|---|
| 主要 CTA（新建、运行、保存） | `accent` |
| 次要按钮、链接 | `text-primary` + border |
| 危险（删除、停止） | `danger` |
| 成功反馈（已保存、已完成） | `success` |
| 工具调用 / 处理中 | `info` |
| 用户决策（追问） | `warning` |

**禁止**：再混用 rose/indigo/emerald/amber 直接写到组件里。颜色一律走 token。

### 2.2 字体

仅保留**两条字体栈**：

- `font-sans`: `"Inter", "PingFang SC", system-ui, sans-serif`
- `font-mono`: `"JetBrains Mono", "SF Mono", "Cascadia Code", monospace`

#### 字号阶梯

| Token | px | 用途 |
|---|---|---|
| `text-2xs` | 11 | 时间戳、辅助标签 |
| `text-xs` | 12 | 列表辅助信息、按钮 sm |
| `text-sm` | 13 | 正文、表单 |
| `text-base` | 15 | 强调段落、卡片标题 |
| `text-lg` | 18 | section 标题 |
| `text-xl` | 22 | 页面 H1 |
| `text-2xl` | 28 | Hero 标题（仅首页"快速开始"用） |

字号比 Tailwind 默认略压缩，对密集运维信息更友好。

### 2.3 间距 / 圆角 / 阴影

- **间距节奏**：4 / 8 / 12 / 16 / 24 / 32 / 48 px（即 `space-1/2/3/4/6/8/12`），不在中间随便取值
- **圆角**：`rounded-md` = 6px（默认）、`rounded-lg` = 10px（卡片）、`rounded-full` = pill（badge）
- **阴影**：暗色环境下减用阴影，改用 border + 微亮的 elevated 背景区分层次。Drawer/Dialog 仅用 `shadow-2xl` 配合 overlay

## 3. 组件库规划

### 3.1 替换 / 升级

| 组件 | 现状 | 改造 |
|---|---|---|
| `Button` | 4 个 variant（primary/secondary/ghost/danger） | 重新映射到 token；新增 `accent`（橙）取代 primary 主色 |
| `Dialog` | 居中模态 | 保留但视觉对齐 token；增加 `size` prop（sm/md/lg/xl） |
| `Input` / `Textarea` | 浅色边框 | 暗色底 + 强 border |
| `MarkdownView` | 已抽出 | 适配暗色（代码块/引用/链接） |

### 3.2 新增

| 组件 | 用途 | 备注 |
|---|---|---|
| `Drawer` | 右侧滑出抽屉，替代部分 Dialog；**AI 助手 / 报告查看**主要载体 | 基于 Radix Dialog（complementary 角色） |
| `Toast` | 操作成功反馈（"已保存"、"已生成报告"） | 引入 `sonner`（10KB） |
| `StatusBadge` | 统一渲染执行状态、文档类型、工具状态 | 字 + 圆点 + 颜色，外形一致 |
| `EmptyState` | 列表空态的引导卡片 | 图标 + 标题 + 描述 + CTA，模板化 |
| `Card` | 替代散在各处的 `bg-white border rounded` | header/body/footer 三段 |
| `KeyHint` | 键盘快捷键提示（`Ctrl+K` 等） | 配合命令面板 |
| `CommandPalette` | `Ctrl+K` 全局搜索 / 跳转 / 发 AI | 引入 `cmdk` |
| `MermaidView` | 真实渲染 Mermaid 源码 | 引入 `mermaid`（懒加载） |
| `ProgressTimeline` | 替代 chat bubble 里的 `<ol>` 进度列表，可折叠、按状态着色 | 配合 P7 工具调用样式 |

### 3.3 约定

- 所有按钮一律走 `<Button>`，不允许 `<button className=...>` 出现在业务代码
- 所有"空 / 加载 / 错误"三态使用 `<EmptyState>` / `<Loader>` / `<ErrorState>`，不再各自手写
- 所有"已保存 / 失败"反馈一律走 Toast，不用 `alert()` 或行内红框

## 4. 信息架构（C 路线）

### 4.1 主导航

从 **6 tab 对象列表** 重构为 **4 tab 任务导向**：

```
┌─ OpsEngine ──────────────────────── 🔍 Ctrl+K  AI 💬  ⚙ ─┐
│                                                          │
│  概览   工作流   执行记录   文档                          │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| Tab | 内容 | 替代 |
|---|---|---|
| **概览** | 快速开始卡片（首次引导）/ 最近活动（执行、文档）/ 资产健康（环境数量、最近巡检） | 新增 |
| **工作流** | 工作流列表 + 集合切换（顶部 segmented control） | 合并旧"工作流" + "集合" |
| **执行记录** | 不变 | "执行" tab |
| **文档** | 不变 | "文档" tab |

**移到右上角入口**：
- 🔍 `Ctrl+K` 命令面板（最高频）
- 💬 AI 助手（任意页面唤起 Drawer）
- ⚙ 设置 → 下拉菜单（含 AI 配置、环境管理、关于）

**为什么环境/设置移走**：日常工作不需要频繁切，但目前在主导航占两个位置；下放到右上角下拉解放主导航。

### 4.2 概览页

零状态（无环境 + 无 API Key）：
```
┌─ 欢迎使用 OpsEngine ────────────────────────────────────┐
│                                                          │
│   3 步开始：                                             │
│                                                          │
│   ① 配置 AI 服务  →  [ 立即配置 ]                        │
│   ② 添加运维环境  →  [ 添加环境 ]                        │
│   ③ 输入运维需求  →  [ 打开 AI 助手 ]（已 disabled）     │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

就绪状态：
```
┌─ 最近活动 ─────────────────────────────────────────────┐
│ • 巡检报告：生产环境（2 小时前）            [ 打开 ]     │
│ • 执行：nginx 重启工作流（昨天 14:30 ✓）   [ 打开 ]     │
│ • 排障会话：CPU 高排查（昨天 10:12）       [ 继续 ]     │
└─────────────────────────────────────────────────────────┘
┌─ 资产 ──────────┐  ┌─ 工作流 ────────┐  ┌─ 文档 ──┐
│ 3 个环境         │  │ 12 个工作流      │  │ 8 份报告 │
│ 7 台 SSH         │  │ 上次执行 5h 前   │  │         │
└──────────────────┘  └──────────────────┘  └──────────┘
```

### 4.3 命令面板（Ctrl+K）

按类型分组：
- **AI** — 直接发问题给 AI（无需打开抽屉）
- **跳转** — 工作流 / 执行 / 文档 / 环境（带搜索）
- **操作** — 新建工作流、运行最近一个、配置 AI 服务...
- **历史会话** — 最近 5 个 AI 对话

## 5. 关键交互流程（B 路线）

### 5.1 AI 助手改成右侧 Drawer

| 现在 | 改造 |
|---|---|
| 居中 Dialog 占满屏幕 | 右侧 480px 宽 Drawer，与主区域共存 |
| 关闭丢失 streaming 上下文 | 关闭只是收起，对话保留；右上角小气泡显示"AI 正在处理中..." |
| 唯一入口在工作流页 | 顶栏 `💬 AI` 按钮 + `Ctrl+I` 快捷键 + 命令面板 |

**收益**：用户可以边看工作流边问 AI；边看执行结果边追问 Agent。

### 5.2 主流程跳转打平

**当前痛点**：巡检流程 4 次跳转
```
chat 生成巡检工作流 → 工作流详情页 → 运行 → 执行详情页 → 生成报告 → 文档 tab → 找到报告
```

**改造后**：
```
chat 生成巡检工作流
  ├ 消息内嵌"运行"按钮 ─────────────→ 直接拉起运行
  │                                       │
  │                                       ↓
  │                                  Toast: "已开始执行" + "查看进度"
  │                                       │
  │                                       ↓ （点 toast）
  └───────────────────────→ 执行详情页（Drawer 形式）
                                          │
                                          ↓ 执行完成自动 Toast
                                  "已完成 · 一键生成报告"
                                          │
                                          ↓ （点 toast）
                                  报告 Drawer 直接打开（不切 tab）
```

具体改动：
- **消息卡片增强**：巡检/工作流消息卡片直接带"运行"按钮，配合 RunWorkflow Wails 调用
- **执行详情**：可作为 Drawer 打开（路由仍支持 deep link 单独页），从对话内嵌入口直达
- **报告 Drawer**：现在的 InspectionReportDialog 改 Drawer，可与执行详情并列；执行完成 toast 触发

### 5.3 Toast 反馈

引入 `sonner`。统一两类反馈：

```
Toast.success("已保存为排障报告", { action: "查看文档" })
Toast.error("LLM 调用失败", { description: "..." })
Toast.info("执行已开始", { action: "查看进度", duration: 5000 })
```

替代当前所有 `alert()` + 内联红框。

### 5.4 Mermaid 真实渲染

引入 `mermaid` npm 包，在 `MarkdownView` 中识别 `lang=mermaid` 的代码块并替换为 `<MermaidView>` 渲染。

懒加载（`import()` 动态导入），避免主 bundle 膨胀：
```ts
const Mermaid = lazy(() => import('./MermaidView'))
```

报告里架构图直接可视化；点图可放大全屏。

### 5.5 ProgressTimeline 折叠

当前 chat 消息的 `<ol>` 进度列表会无限增长。改造：
- 默认折叠为 `"5 步采集 · 3 个工具调用 [展开]"`
- 展开后按类型分组显示（环境加载 / 工具调用 / 模型推理 / 保存）
- 工具调用单独成卡片，可点开看完整输入输出

### 5.6 target_select 视觉强化

现在 amber 按钮在长 progress 末尾不够醒目。改造：
- 整条消息变成 `warning` 主题（左边竖线 + 浅琥珀背景）
- 按钮区域更大，配上下文文案"Agent 等待你的选择"
- 未响应时其他消息输入区显示 banner 提示

### 5.7 错误处理

替换所有 `alert()` 和内联红框：
- 同步失败 → Toast.error 带 "重试" action
- 流程失败 → 在对话气泡内显示带颜色的失败块 + 重试链接
- 网络失败 vs 配置失败 vs 模型失败 → 沿用 P0 的分类前缀，加图标区分

## 7. 依赖清单

新增 npm 依赖：

| 包 | 大小 | 用途 | 必要性 |
|---|---|---|---|
| `sonner` | ~10KB | Toast | 必须（替代 alert） |

无需新增：
- 不引入 UI 框架（shadcn / mantine）—— 与现有"直接写 Tailwind"风格一致
- 不引入主题切换库 —— 不做亮色模式
- 不引入额外动画库 —— Tailwind + Radix 内置 transition 已够

## 8. 风险与开放问题

### 风险
1. **暗色模式下 React Flow 默认主题需调**：工作流画布是浅色基底，需要适配暗色边/连线/节点
2. **现有 InspectionReportDialog 已有自定义 Markdown 渲染**：MermaidView 集成需小心不要破坏现有逻辑
3. **首页重构影响所有 deep link**：现有 `/` 路由是工作流列表，改成概览后需检查
4. **`Ctrl+K` 与 Wails 系统快捷键可能冲突**：需测试

### 开放问题
1. **图标方案**：lucide vs tabler？lucide 风格中性，tabler 更细。倾向 **lucide**（社区更主流）
2. **集合 tab 合并方式**：顶部 segmented control 还是侧边切换？倾向 segmented
3. **AI Drawer 是否可拖宽**：第一版固定 480px；后续如果用户在窄屏（笔记本）抱怨，再加拖动
4. **是否保留 6-tab 的旧导航作为"专家模式"开关**：默认 no——做了不彻底反而割裂

## 9. 成功标准

重构完成后，下面这些应该都能做到：

- 新用户打开应用 → 看到概览页 → 3 步内启动第一次巡检
- 任意页面按 `Ctrl+I` 唤起 AI 抽屉，不打断当前上下文
- 巡检流程从"用户输入需求"到"看到报告"，路径上的每一步都有就地 CTA，不需要主动切 tab
- 架构报告的 Mermaid 直接可视化，可缩放可全屏
- 所有错误反馈都有"重试"或"如何修复"指引，不再裸 `alert()`
- 长对话的 progress 列表可折叠，工具调用细节可展开
- 所有颜色都来自 token，无散落的 `text-rose-600` 直写
