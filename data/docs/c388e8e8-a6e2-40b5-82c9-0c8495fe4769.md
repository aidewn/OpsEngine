## 风险与建议

关键风险
- **日志导出权限拒绝（项 6）**：`otelopscol` 上报日志到 Google Cloud 时持续报 `PermissionDenied`，提示 `logging.googleapis.com` 权限不足，会导致该实例的遥测数据丢失，监控盲区。
- **疑似未授权的 SSH 登录（项 7）**：系统日志中出现来自外部 IP `64.118.149.168` 的 `root` 密码登录记录，若该 IP 非已知管理来源，则存在主机已被横向移动或爆破的风险。

修复建议
- **修复日志导出权限**：检查该实例关联的服务账号是否具备 `roles/logging.logWriter` 角色；若为默认 Compute Engine 服务账号，需确认其是否被限制或错误配置了访问范围，确保授予 `logging.googleapis.com` 的写权限。
- **处置可疑 SSH 登录**：  
  立即核实 `64.118.149.168` 是否为授权管理端；若非授权，应立刻删除该 IP 相关会话，重置 `root` 密码，审计 `/var/log/auth.log` 中的操作痕迹。  
  加固 SSH 配置：编辑 `/etc/ssh/sshd_config` 设置 `PermitRootLogin prohibit-password` 或 `no`，启用 `PasswordAuthentication no` 强制密钥认证，并考虑通过 `AllowUsers` 或防火墙限制来源 IP。
- **关闭不必要的 SMTP 服务（项 5）**：若本机无需收发邮件，建议执行 `systemctl disable --now exim4` 并卸载 `exim4-daemon-light` 包，减少暴露面。

需要确认的问题
- 外部 IP `64.118.149.168` 是否为团队已知的巡检来源或跳板机？若不是，需立即启动安全事件调查。
- 该服务器是否计划运行 Docker 容器（项 9 显示未安装）？若需要，应补充 Docker 引擎安装步骤；若不需要，可忽略该命令失败。
